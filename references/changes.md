# 修改已有代码

适用于功能增加、缺陷修复、重构或结构审查；确认和只读边界沿用入口约定。

从问题所在位置及直接调用关系理解它在实际使用流程中的作用，复用项目约定与已知上下文。发现共享影响、状态或数据写入风险、证据不足时再扩展调查。用户点名的组件是线索，不能单凭它界定完成范围。

发现关联问题时，判断它是否妨碍本次约定结果。“旧问题”描述来源，不能决定是否需要修复：阻碍当前目标、且属于授权范围的必要工作应继续处理；无关技术债不顺带重写。有一项依赖受阻时，先完成不依赖它的必要工作，并说明剩余影响，避免用一个环境缺口代替整个任务的完成判断。

优先修改拥有该职责和规则的位置。若原边界承载不了需求，说明具体矛盾，作必要结构调整；涉及未定职责或明显扩围时按入口确认。最小差异不一定是最小维护成本，但结构调整也需要当前证据。改后检查是否多了一份规则、不必要的依赖或意外的失败语义。

修改使使用、接口、架构或部署说明失效，或有关键决定需要长期保留时，读取 [文档维护](documentation.md) 更新合适位置。文档帮助下一次正确使用和修改，不是逐次操作日志；无文档影响的局部修改不额外留档。
