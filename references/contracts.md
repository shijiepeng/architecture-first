# 模块合同与配置生效

从代码、入口和调用关系确认模块边界。界面、传输协议、业务规则和基础设施应有清楚职责，但不要求小项目每一层都独立建目录。跨模块走其公开合同，不读取另一个模块的私有实现来绕过合同。

同一配置或业务规则明确一个权威来源。需要默认值、数据库覆盖、缓存或回退时，说明优先级及生效时机，不维护多份可独立修改的隐含规则。

特别检查这些容易出现的脱节：

- 可编辑配置：从界面保存，经过持久化和加载，直到实际执行使用该值。保存成功不能替代生效验证。
- 提示词与规则文件：确认调用路径实际读取；目录存在不代表功能已接入。
- 类型与 schema：外部边界确实执行必要校验；存在定义不代表运行时已经校验。
- 插件：依赖、输入输出、失败含义和必要的生命周期明确；不是只把文件移到 plugins 目录。
- 业务结果：能够追溯到必要的输入与规则版本；记录粒度按业务需要决定，不默认建设大型审计系统。
